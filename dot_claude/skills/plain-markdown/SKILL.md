# plain-markdown — 装飾を排した素のマークダウン

マークダウンをファイルや外部ツールへ書き出す時、太字・不要なコードブロック・各種装飾を避け、見出しと地の文と箇条書きで内容そのものを伝える。装飾は情報量を増やさずノイズだけ増やしがちで、書き手ごとにばらつく。ここで一律に削ぐことで、書き出す成果物の見た目を揃える。

## 適用範囲

- 適用する: `.md` などファイルへの書き出し、外部ツール（Notion・Slack・GitHub PR 本文など）への markdown 書き込み。
- 適用しない: このターミナルでのチャット返信そのもの。

## ルール

### 太字を使わない

`**...**` / `__...__` による太字は一切使わない。強調したい・見出しのように見せたい時は、装飾ではなく構造で表す。

- 節を区切りたい → 見出し（`##` / `###`）にする。
- 箇条書きのラベルが要る → `項目: 説明` と素の文で書く（`**項目**:` にしない）。

理由: 太字は「重要そう」を演出するだけで構造を持たない。見出しや箇条書きに置き換えると、文書の骨格が読み手にも diff にも残る。markdownlint では見出し代わりの強調を禁じる MD036 と方向性が一致する（太字全廃そのものはハウスルール）。

悪い例: `**設計方針**: まず A を決める`
良い例: 見出し `### 設計方針` にする、または `設計方針: まず A を決める`

### コードブロックは実コードのみ

フェンス付きコードブロックで囲ってよいのは実コードだけ。ソースコード、シェルコマンド、設定ファイルの中身に限る。ログ・コマンド出力・プレーンな文章・強調目的の囲い込みには使わない。

- 単体のパス・識別子・短いコマンドは囲わず、インライン code（バッククォート1組）で書く。
- 出力やログを見せたい時は、必要な行だけ地の文や箇条書きで引用する。

理由: コードブロックは「これはコードだ」という意味を持つ。コード以外を囲うとその意味が嘘になり、画面も縦に伸びる。実コードを囲う時は markdownlint の MD040 に従い言語タグを付ける。

### 装飾を使わない

次は使わない。

- 絵文字（見出し・箇条書き頭・文中のいずれも）。
- 水平線 `---`。区切りが要るなら見出しにする（YAML frontmatter の `---` は別物で可）。
- blockquote / callout（`>` による注記・囲み）。
- 装飾目的の表。表は本来の表形式データ（行 × 列に意味があるもの）だけに使い、強調やレイアウト目的では使わない。

理由: いずれも内容を足さず見た目だけ飾る。素の見出し・箇条書き・地の文で同じ情報は十分伝わる。

### 読者目線で書く（作業上のメタを混ぜない）

成果物には読者に必要な内容（何を・なぜ）だけを書く。指示者と作業者の間の取り決め・段取り・構成方針は書かない。

- 悪い例: `読者に応じて2部構成にする。前半は PdM 向け、後半は開発者向け` — なぜそう分けたかは読者に無関係。
- 良い例: オーディエンス別の見出し（`PdM 向け` / `構築手順`）だけ置き、分けた理由の説明文は載せない。

書き出す前に各文を「読者に必要か / 進め方の説明か」で選別し、後者は削る。

理由: 構成意図や作業段取りはメタ情報で、読者のノイズになる。見出しの存在自体が導線になるので、意図の説明は要らない。

## 整形を頼まれた時

既存マークダウンの整形を頼まれたら、上のルールに反する箇所（太字・非コードのフェンス・絵文字・水平線・blockquote・装飾表）を、意味を保ったまま素の表現に置き換える。内容そのものは変えない。
