# tldr — 読む文章を自分向けに書き直す

長い文章、前置き、クッション言葉、感嘆符、経緯の語りを落とし、判断に要る事実と、自分がやることと、返信文だけを残す。結果は LINE Seed JP のページにしてブラウザで開く。

## 入力

`/tldr` の引数に次のどれかを 1 つ以上渡す。引数が無ければクリップボードを読む。

- Slack のメッセージ URL
- Chatwork のメッセージ URL
- Notion のページ URL
- 上記以外の URL
- ファイルパス
- 平文

`--keep` を付けると、ページを scratchpad ではなくデスクトップに残す。

```bash
pbpaste
```

## 取り込み

ソースごとに、本文と前後の文脈を次の範囲で集める。読み込んだ範囲は 出典 に書く。

### Slack

URL `https://<ws>.slack.com/archives/<channel_id>/p<16 桁>` から `channel_id` と `message_ts` を取る。`message_ts` は 16 桁の末尾 6 桁の前に `.` を入れた値。URL に `thread_ts=` があれば、その値をスレッドの親にする。

1. `slack_read_thread` で親と返信をすべて読む。
2. `slack_read_channel` を `limit: 20` で読み、同じチャンネルの直近 20 件を背景にする。

### Chatwork

URL `https://www.chatwork.com/#!rid<room_id>-<message_id>` から `room_id` と `message_id` を取る。

1. `get_room_message` で該当メッセージを読む。
2. 本文の `[rp aid=... to=<room_id>-<message_id>]` を辿り、返信元が無くなるまで `get_room_message` を繰り返す。
3. `list_room_messages` を `force: 1` で読み、同じ部屋の直近 20 件を背景にする。

### Notion

`notion-fetch` に URL を渡してページ本文を読む。`truncated` が真なら、その旨を 出典 に書く。

### それ以外の URL、ファイル、平文

URL は `WebFetch`、ファイルは `cat`、平文はそのまま本文にする。背景は集めない。

## 残すものと落とすもの

残すのは、自分が判断するのに要るものだけ。

- 自分宛ての質問、依頼、期限、確認事項
- 日付、数値、固有名、決定事項、決定待ちの選択肢
- 誰が言ったか

落とすのは次のもの。落としたことは書かない。

- 挨拶、前置き、締め、クッション言葉、謝罪
- …、なのですが、！、絵文字、顔文字
- 経緯の語り、感情、感想、相づち
- 同じ内容の繰り返し、引用の再掲

英語の原文は翻訳しない。本文に英語が混ざっていれば、その箇所は原文のまま載せる。

## 型

ソースごとに次の 5 節をこの順で出す。節名は固定。上限を超えた分は落とす。

1. 概要: 何の話で、自分に何を求めているか。2 文以内。
2. 要対応: 自分がやること、答えること。1 件 1 行、4 件以内。期限があれば行末に書く。無ければ なし の 1 行。
3. 返信案: 要対応の各件に対応する返信文。1 件 3 文以内。コピーして投稿できる完成形。要対応が なし なら省く。
4. 事実: 日付、数値、固有名、決定事項だけ。6 件以内。
5. 出典: ソースの URL、発言者、投稿日時、読み込んだ範囲。

複数ソースは 1 ページに縦に並べ、ソースごとに 5 節を繰り返す。統合しない。

1 文は 40 字以内。超えたら 2 文に分けるか、箇条書きにする。

## 返信案の声

返信案は本人が書く文として出す。宛先タグ、メンション、`[rp]` や `[To:]` は含めない。返信ボタンと宛先は UI 側で付ける。

身内の声を既定にする。

- です・ます。1 件 1〜2 文、長くても 3 文。
- 文末は 承知です！、修正しました！ のように ！ で締めてよい。
- 相手の問いにまず答え、理由は後ろに 1 文で付ける。
- 謝罪、前置き、締めの定型文を書かない。
- 案が分かれる話は、自分の推しを 1 つ言い切る。

相手が明らかに社外か、部屋名や肩書きから他社と分かる時だけ丁寧寄りに倒す。恐れ入ります、ご回答ありがとうございます、を使い、！ を減らす。判断できなければ身内の声にする。

## 出力

1. `template.html` を複製し、プレースホルダを埋める。`<article>` をソースの数だけ繰り返す。
2. `<scratchpad>/tldr-<YYYYMMDD-HHMM>.html` に保存する。`--keep` なら `~/Desktop/tldr-<題材>.html` に保存する。
3. `open` でブラウザに出す。
4. ターミナルには、保存先の絶対パスと、要対応の件数だけを 1 行で書く。

```bash
open "<保存先>"
```

## 点検

保存前に次を実行し、出力が 0 行になるまで直す。

文の長さと落とすべき語を機械で点検する。

```bash
python3 - "<保存先>" <<'EOF'
import re, sys, html
s = open(sys.argv[1], encoding="utf-8").read()
s = re.sub(r"<(style|script|pre)\b.*?</\1>", "", s, flags=re.S)
t = html.unescape(re.sub(r"<[^>]+>", "\n", s))
for x in (x.strip() for x in re.split(r"[。\n]", t)):
    if len(x) > 40:
        print("40字超:", x)
    if re.search(r"[！!]|…|\.\.\.|なのですが|とは思いますが", x):
        print("落とす語:", x)
EOF
```

返信案の ！ は本人の声なので許す。点検で返信案の行が出たら、その行だけ無視する。

節ごとの件数を目で数える。要対応 4 件、事実 6 件、概要 2 文を超えていたら落とす。

## 対象外

- 投稿、返信、リアクション。送るなら会話の中で Slack や Chatwork の MCP を直接頼む。
- 自分が書いた文章の整形。clean-markdown と slack-report の担当。
- 仕組みの解説。sensei の担当。
