# commit — コミットを一気通貫で実行

ステージからコミットまでを確認なしで自律的に完了させる。新しいコミットを作る経路はこのスキルに一本化し、`git commit` を Bash で直接組み立てない。

## 即終了条件

- 新規にステージされる変更に秘密情報（`.env` 系ファイル・秘密鍵・API トークン・パスワードらしき文字列）の混入が疑われる → 警告して停止、コミットしない（履歴に入った秘密の除去は極めて困難）。
- ステージ後にコミット対象が無い → 「コミットするものがありません」と一言だけ伝えて終了。

## 手順

1. `git status --short` と `git diff` / `git diff --staged` で変更内容を把握し、即終了条件を判定する。
2. `git add -A` で作業ツリーの全変更をステージする。
3. ステージされた diff から下記の規約で日本語・1行のメッセージを組み立てる。
4. `git commit -m "<メッセージ>" -m "<署名トレーラー>"` を実行する。署名トレーラーは環境が指定する `Co-Authored-By: ...` 行をそのまま使う（省略しない）。
5. コミットハッシュ（短縮）とメッセージを1行で報告する。

## メッセージ規約

- サマリは `<prefix>: <日本語の説明>` の1行のみ。説明の本文は付けない（署名トレーラーを除く）。
- prefix は diff の内容から自動で選ぶ（引数での指定は受け付けない）：`feat` 新機能・新規追加 / `fix` バグ修正 / `docs` ドキュメントのみ / `chore` ビルド・設定・雑務 / `refactor` 挙動を変えない整理 / `style` フォーマットのみ / `test` テスト / `perf` パフォーマンス。
- 種類が混在する場合は主目的の prefix を1つ選ぶ。
- 既存履歴（`feat: 〜を追加` 形式）の語調に揃える。

## やらないこと

- `git push` はしない。コミットまでで終了する。
- 確認・メッセージ案の事前承認を求めない（即終了条件を除く）。
- `--no-verify` は付けない。hook が失敗したら握りつぶさず報告して止まる。
- コミットの分割はしない（全変更を1コミット）。
