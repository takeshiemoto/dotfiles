# commit — コミットを一気通貫で実行

「コミットして」と言われたら、ステージからコミットまでを確認なしで自律的に完了させる。人間の介在を最小化するのが目的。

ユーザーの明示指示だけでなく、タスクの一部として自分（エージェント）がコミットすると決めた時も、必ずこの手順を経由する。`git commit` を Bash で直接組み立てない —— 新しいコミットを作る経路はこのスキルに一本化する。

## 手順

1. 状態確認：`git status --short` と `git diff` / `git diff --staged` で作業ツリーの変更内容を把握する。
2. 秘密情報チェック（安全弁 b）：新規にステージされる変更に、`.env` 系ファイル・秘密鍵・API トークン・パスワードらしき文字列が含まれていないか確認する。混入が疑われたら、ここで止めてユーザーに警告し、コミットしない（git 履歴に一度入った秘密の除去は極めて困難なため、ここだけは自律実行の例外）。
3. ステージング：`git add -A` で作業ツリーの全変更をステージする。
4. 差分ゼロの確認（安全弁 a）：ステージ後にコミット対象が無ければ、何もせず黙って終了する（「コミットするものがありません」と一言だけ伝える）。
5. メッセージ生成：ステージされた diff の内容から、後述の規約で日本語・1行のコミットメッセージを組み立てる。
6. コミット実行：`git commit -m "<メッセージ>" -m "<署名トレーラー>"` を実行する。確認は取らない。署名トレーラーは Claude Code が環境で指定する `Co-Authored-By: ...` 行をそのまま使う（外さない）。
7. 結果報告：コミットハッシュ（短縮）とメッセージを1行で報告する。

## コミットメッセージ規約

- 形式：サマリは `<prefix>: <日本語の説明>` の1行のみ。説明文の本文は付けないが、Claude Code の `Co-Authored-By` 署名トレーラーは例外として必ず本文末尾に残す（この規約を理由に署名を省略しない）。
- 言語：説明は日本語。
- プレフィックス：diff の内容から以下より自動で選ぶ（引数での指定は受け付けない）。
  - `feat:` 新機能・新規追加
  - `fix:` バグ修正
  - `docs:` ドキュメントのみの変更
  - `chore:` ビルド・設定・雑務（依存更新、設定ファイル等）
  - `refactor:` 挙動を変えないコード整理
  - `style:` フォーマット・空白等（挙動に影響しない）
  - `test:` テストの追加・修正
  - `perf:` パフォーマンス改善
- 複数の種類が混在する場合は、変更の主目的にあたるプレフィックスを1つ選ぶ。
- 既存リポジトリの履歴（`feat: 〜を追加` 形式）の語調に揃える。

## やらないこと

- `git push` はしない。コミットまでで終了する。
- 確認を取らない（安全弁 a / b に該当する場合を除く）。メッセージ案の事前承認も求めない。
- `--no-verify` は付けない。リポジトリ側の pre-commit hook（husky / lint-staged 等）は尊重する。hook が失敗してコミットが失敗した場合は、握りつぶさず失敗内容を報告して止まる。
- コミットの分割はしない（全変更を1コミットにまとめる）。
