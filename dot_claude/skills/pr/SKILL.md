# pr — テンプレート順守で PR を作る

`/pr <base>` で push から PR 作成までを**確認なしで自律実行**する。最優先はリポジトリの**テンプレート厳守**。前提が崩れる時（後述「停止条件」）だけ止める。コミット生成は範囲外（`commit` スキルの責務）。未コミット変更があっても**コミットしない・警告のみ**。

## 手順

1. **前提チェック**：git リポジトリ・`gh auth status`・ベース引数の3点。欠ければ停止。
2. **差分確認**：ベースに対し差分ゼロなら「PR にする差分がない」と伝えて終了。
3. **未コミット警告**：`git status --short` に変更があれば「PR に含まれない」と一言警告して続行。
4. **テンプレート探索**（後述）：見つからなければ停止。
5. **本文・タイトル生成**（後述）：文体は常体。
6. **push**：上記の停止条件を全通過してから `git push -u origin HEAD`。push を最後に置くのは、中断する PR のブランチ公開を避けるため。拒否されたら **force せず**理由を報告して停止。
7. **PR 作成/更新**：既存 PR があれば本文更新（後述）、なければ `gh pr create --base <base> --head <current> --draft --assignee takeshiemoto --title "<title>" --body-file <tmp>`。assignee は常に `takeshiemoto` 固定。本文はエスケープ事故回避のため一時ファイル経由。
8. **報告**：PR の URL・ベース・draft を1行で。

## ベースブランチ

引数で必須指定（推測・自動検出しない）。未指定なら止めて聞く。リモートに無ければ停止。

## テンプレート探索

GitHub 標準配置を大文字小文字・拡張子（`.md`/`.txt`/無し）のゆれ込みで探す。

```bash
find . \( -path './.github/PULL_REQUEST_TEMPLATE*' \
        -o -iname 'PULL_REQUEST_TEMPLATE.md' \
        -o -ipath './docs/PULL_REQUEST_TEMPLATE*' \) -not -path './.git/*'
```

- 1件 → それを使う。
- 0件 → **停止して確認**（勝手に作らない）。
- `PULL_REQUEST_TEMPLATE/` に複数 → どれを使うか聞く。

## 本文の埋め方

テンプレートに厳格に従う。これが核心。素材は `git log <base>..HEAD` と `git diff <base>...HEAD`（3点表記）。

- **構造を壊さない**：見出し・節順・HTML コメントはそのまま。節を増減しない。
- **diff の写経はしない**：本文は差分の要約ではなく、レビュアーが diff から読み取りにくい**意図・全体像・判断理由**を補うもの。変更は**観点（なぜ／何を）単位**でまとめ、ファイル/行単位で書かない。呼び出し側追従・リネーム・import 整理など自明な機械的差分は省く（残すなら1行）。
- **バッククォートは最小限**：識別子を機械的に全部囲まない。記号入りコード片や誤読箇所だけ、同じ語は初出のみ。
- **diff から導けない節**（関連 Issue・テスト手順・スクショ等）は捏造せず**「なし」と明記**。空欄放置もしない。
- **チェックボックス**は原則未チェック（明確に該当するものだけチェック）。

### バッドプラクティス：変更点の書きすぎ

実装の細部を diff から写経した例。これは避ける。

```markdown
## 変更点
- 〇〇セクションを既存の△△に倣い Section / View / Form の3コンポーネントに分割した。
- 状態管理は既存の `useEditModeState` フックを再利用する。「変更」押下で編集フォームを表示し、「キャンセル」で読み取り表示に戻す。
- フォームは react-hook-form でラジオを管理する。初期選択は「□□」とし、枠は `DefinitionList` の `isEditState` で青枠表示にする。
- 上記に伴い Section が `companyId` を不要にしたため、呼び出し側の受け渡しを削除した。
- locale に「△△」を追加した。
```

何が問題か：

- フック名・ライブラリ名・props 名・色など**実装の細部を列挙**＝diff の写経。レビュアーは diff で読める。
- 「呼び出し側の受け渡し削除」「locale 追加」は**見れば自明な機械的差分**。観点ではなく作業ログになっている。
- 一節が長く、**意図・全体像・判断理由**（なぜこの分割か、なぜスタブか）が細部に埋もれる。

良い形（観点単位・diff から読めないことだけ）：

```markdown
## 変更点
- 外部連携セクションを読み取り専用から許可/不許可の編集対応にした。構成は既存の契約情報セクションに倣う。
- 保存はバックエンド未実装のためスタブ（API 配線は別タスク）。送信箇所は TODO で明示。
```

## タイトル

**まずリポジトリ内のタイトル規約を機械的に探す**（テンプレ探索と同格の必須手順）。

```bash
ls CONTRIBUTING.md .github/CONTRIBUTING.md docs/CONTRIBUTING.md CLAUDE.md AGENTS.md 2>/dev/null
grep -rilE 'semantic.?pull.?request|commitlint' .github 2>/dev/null
```

見る場所：`CONTRIBUTING.md`（ルート/`.github`/`docs`）、PR テンプレ冒頭の HTML コメント、`CLAUDE.md`/`AGENTS.md`、`.github/workflows/*` や `.github/semantic.yml`（PR タイトル lint）、`commitlint.config.*` 等（許可 type/scope）。

1. **規約あり** → 確認なしで厳格適合。衝突時は **CI で落ちる lint 設定を優先**。
2. 規約が要求する情報（Issue 番号等）が**欠けていれば停止**して聞く。
3. **規約なし** → `commit` スキル準拠の `<prefix>: <日本語の説明>` 1行。コミット1個ならそのメッセージ流用、複数なら主目的を1本に要約。prefix 混在時は主目的の prefix（迷えば `feat` > `fix` > その他）。

## 既存 PR の場合

`gh pr view --json number,url,state` で検出。あれば新規作成せず `gh pr edit <number> --body-file <tmp>` で**本文のみ**更新。

- **タイトルは触らない**（手修正を潰さない）。
- 本文は `<base>..HEAD` から**全面再生成・置換**（手追記は保持されない旨を報告に1行添える）。

## 停止条件（自律実行の例外）

以下では止めて確認・報告する：ベース引数未指定／指定ベースがリモートに無い／テンプレ0件／`PULL_REQUEST_TEMPLATE/` 複数で決められない／タイトル規約が要求する情報が無い／`git push` 拒否（force しない）／git リポジトリでない・`gh` 未認証・差分なし。

停止時は、**そこまでに判明した警告・事実（未コミット変更・現在ブランチ・ベース・差分有無）も併せて伝える**。

## やらないこと

- コミットしない・force push しない。
- テンプレート構造を改変しない（節の増減・並べ替え・コメント削除）。
- **draft 以外で作らない**（常に `--draft`）。
- 停止条件以外で確認を取らない（本文・タイトル案の事前承認も求めない）。
