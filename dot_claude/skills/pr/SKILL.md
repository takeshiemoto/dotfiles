# pr — テンプレート順守で PR を作る

`/pr <base>` または「PR 作って」と言われたら、push から Pull Request 作成までを**確認なしで自律的に**完了させる。ただし PR はリポジトリの**テンプレートに厳格に従う**ことを最優先とし、テンプレートが無いなど前提が崩れる時だけ止めて確認する。コミットの生成は範囲外（既存の `commit` スキルに委ねる）。

## 守備範囲

- **やる**：現在ブランチの push、テンプレート探索、本文・タイトル生成、`gh pr create --draft`、既存 PR の本文更新。
- **やらない**：コミットの生成（`commit` スキルの責務）。未コミットの変更があってもコミットしない。

## 手順

1. **前提チェック**：git リポジトリであること、`gh auth status` が通ること、ベース引数が指定されていることを確認する。いずれか欠ければ止めて伝える（下記「停止条件」）。
2. **ベース確定**：引数のベースブランチ（例 `develop`）を採用する。**引数が無ければ止めて「ベースブランチを指定してくれ」と聞く**。推測で `main` 等に向けない。
3. **差分の有無**：現在ブランチがベースと同一、またはベースに対し差分（コミット）がゼロなら、`PR にする差分がない` と一言伝えて終了する。
4. **未コミット警告**：`git status --short` に未コミットの変更があれば、「これらは PR に含まれない（コミットされていない）」と一言警告してから続行する。コミットはしない。
5. **テンプレート探索**：後述の標準配置を探す。**見つからなければ止めてユーザーに確認**する（独自構成をでっち上げない）。複数候補（`PULL_REQUEST_TEMPLATE/` ディレクトリ）があれば、どれを使うか止めて聞く。
6. **本文生成**：`<base>..HEAD` のコミットログと diff を素材に、テンプレートの構造を厳守して本文を埋める（後述「本文の埋め方」）。文体は**常体**。
7. **タイトル生成**：リポジトリ内のタイトル規約に従う（後述「タイトル」）。規約が要求する情報が欠ければ止めて聞く。
8. **push**：ここまでの停止条件（テンプレ探索・タイトル規約）をすべて通過してから `git push -u origin HEAD` で現在ブランチをリモートへ送る。**push を最後段に置くのは、テンプレ未発見等で中断する PR のためにブランチを公開してしまう副作用を避けるため**（push は取り消しにくいので、止まりうる検証の後ろに置く）。non-fast-forward 等で拒否されたら、**force は付けず**理由を報告して止まる。
9. **既存 PR の確認**：現在ブランチに既存 PR があれば**新規作成せず本文を更新**する（後述「既存 PR の場合」）。
10. **PR 作成**：`gh pr create --base <base> --head <current> --draft --title "<title>" --body-file <tmp>` を実行する。本文はシェルのエスケープ事故を避けるため一時ファイルに書いて `--body-file` で渡す。
11. **結果報告**：作成（または更新）した PR の URL・ベース・draft であることを1行で報告する。

## ベースブランチ

- **引数で必須指定**（例 `/pr develop`）。自動検出・推測はしない。
- 未指定で呼ばれたら止めて聞く。指定されたブランチがリモートに存在しなければ止めて伝える。

## テンプレート探索

GitHub 標準の配置を、大文字小文字・拡張子（`.md` / `.txt` / 無し）のゆれを含めて順に探す：

| 配置 | 例 |
|---|---|
| `.github/` 直下 | `.github/PULL_REQUEST_TEMPLATE.md` |
| リポジトリルート | `PULL_REQUEST_TEMPLATE.md` |
| `docs/` 直下 | `docs/PULL_REQUEST_TEMPLATE.md` |
| 複数候補ディレクトリ | `.github/PULL_REQUEST_TEMPLATE/*.md` |

```bash
find . \( -path './.github/PULL_REQUEST_TEMPLATE*' \
        -o -iname 'PULL_REQUEST_TEMPLATE.md' \
        -o -ipath './docs/PULL_REQUEST_TEMPLATE*' \) -not -path './.git/*'
```

- 1件見つかればそれを使う。
- **0件なら止めてユーザーに確認**する（テンプレ順守が絶対のため、勝手に作らない）。
- `PULL_REQUEST_TEMPLATE/` に複数あれば、どれを使うか止めて聞く。

## 本文の埋め方

テンプレートに**厳格に従う**。これがこのスキルの核心。

- **構造を壊さない**：見出し・節の順序・HTML コメント（`<!-- ... -->`）はそのまま残す。節を勝手に増減しない。
- **素材**：`git log <base>..HEAD` と `git diff <base>...HEAD`（GitHub の PR 差分と同じ3点表記）から、各節に対応する内容を埋める。
- **文体は常体**（だ・である調）。
- **導ける節**（概要・変更点・背景など）はコミット/diff から埋める。
- **diff から導けない節**（関連 Issue・テスト手順・スクリーンショット等）は、**捏造せず「なし」と明記する**。空欄放置（書き忘れに見える）も推測での捏造もしない。
- **チェックボックス**は原則未チェックのまま残す（内容から明確に該当すると言えるものだけチェック）。

## タイトル

1. **リポジトリ内にタイトル規約があれば、それに適合させる**。規約の在り処を次から探す：
   - `CONTRIBUTING.md`
   - PR テンプレート自身の冒頭やコメントでの指定
   - リポジトリの `CLAUDE.md` / `AGENTS.md`
   - PR タイトル lint（`semantic-pull-request` 等の Actions、`commitlint` 設定）
2. 規約が**必要とする情報が欠けている**（例：Issue 番号やチケット ID が見つからない）場合は、止めてユーザーに聞く。
3. **規約が見つからなければ** `commit` スキル準拠の `<prefix>: <日本語の説明>` の1行にする。
   - ブランチのコミットが1個ならそのメッセージを流用、複数なら変更の主目的を表す1本に要約する（主目的のコミットメッセージをそのまま流用してよい）。
   - prefix が混在する複数コミット（`feat` と `fix` 等）を1本化するときは、**変更の主目的の prefix を採る**（新機能を含むなら `feat`、それ以外は影響の最も大きい変更の prefix）。迷ったら `feat` > `fix` > その他の順で優先する。

## 既存 PR の場合

現在ブランチに既に PR があれば（`gh pr view --json number,url,state` で検出）、**新規作成はせず本文を更新**する：

```bash
gh pr edit <number> --body-file <tmp>
```

- 更新するのは**本文のみ**。**タイトルは触らない**（手で直したタイトルを潰さないため）。
- 本文は `<base>..HEAD` から**全面再生成して置換**する（テンプレ順守のため）。既存本文への手追記は保持されない — その旨を結果報告に1行添える。
- 更新後はその PR の URL を報告する。

## 停止条件（ここだけは自律実行の例外）

次のいずれかでは、処理を止めてユーザーに確認・報告する：

- ベースブランチの引数が未指定。
- 指定ベースがリモートに存在しない。
- テンプレートが1件も見つからない。
- `PULL_REQUEST_TEMPLATE/` に複数候補があり、どれを使うか決められない。
- タイトル規約が要求する情報（Issue 番号等）が見つからない。
- `git push` が non-fast-forward 等で拒否された（force はしない）。
- git リポジトリでない／`gh` が未認証／ベースに対し差分がない。

停止して報告する際は、**そこまでに判明した警告・事実（未コミット変更の有無・現在ブランチ・ベース・差分の有無など）を併せて伝える**。停止点より前の手順（未コミット警告等）で得た情報を黙って捨てない。

## やらないこと

- **コミットしない**（`commit` スキルの責務。未コミット変更は警告のみ）。
- **force push しない**。
- **テンプレートの構造を改変しない**（節の増減・並べ替え・コメント削除をしない）。
- **draft 以外で作らない**（常に `--draft`）。
- 停止条件以外で確認を取らない（本文・タイトル案の事前承認も求めない）。
