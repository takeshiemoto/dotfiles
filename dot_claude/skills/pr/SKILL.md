# pr — テンプレート順守で PR を作る

`/pr <base>` で push から PR 作成までを**確認なしで自律実行**する。最優先はリポジトリの**テンプレート厳守**。前提が崩れる時（後述「停止条件」）だけ止める。コミット生成は範囲外（`commit` スキルの責務）。未コミット変更があっても**コミットしない・警告のみ**。

## 手順

1. **前提チェック**：git リポジトリ・`gh auth status`・ベース引数の3点。欠ければ停止。
2. **差分確認**：ベースに対し差分ゼロなら「PR にする差分がない」と伝えて終了。
3. **未コミット警告**：`git status --short` に変更があれば「PR に含まれない」と一言警告して続行。
4. **テンプレート探索**（後述）：見つからなければ停止。
5. **本文・タイトル生成**（後述）：文体は常体。
6. **push**：上記の停止条件を全通過してから `git push -u origin HEAD`。push を最後に置くのは、中断する PR のブランチ公開を避けるため。拒否されたら **force せず**理由を報告して停止。
7. **PR 作成/更新**：既存 PR があれば本文更新（後述）、なければ `gh pr create --base <base> --head <current> --draft --assignee takeshiemoto --title "<title>" --body-file <tmp>`。assignee は常に `takeshiemoto` 固定。本文はエスケープ事故回避のため一時ファイル経由。
8. **報告**：PR の URL・ベース・draft を1行で。

## ベースブランチ

引数で必須指定（推測・自動検出しない）。未指定なら止めて聞く。リモートに無ければ停止。

## テンプレート探索

GitHub 標準配置を大文字小文字・拡張子（`.md`/`.txt`/無し）のゆれ込みで探す。

```bash
find . \( -path './.github/PULL_REQUEST_TEMPLATE*' \
        -o -iname 'PULL_REQUEST_TEMPLATE.md' \
        -o -ipath './docs/PULL_REQUEST_TEMPLATE*' \) -not -path './.git/*'
```

- 1件 → それを使う。
- 0件 → **停止して確認**（勝手に作らない）。
- `PULL_REQUEST_TEMPLATE/` に複数 → どれを使うか聞く。

## 本文の埋め方

テンプレートに厳格に従う。これが核心。

**PR 本文は「なぜ変えたか（背景・目的）」と「何をしたか（変更の全体像）」をレビュアーの高さで書く。** 読み手は diff を読める前提なので、diff から読み取りにくい意図・全体像だけを補う。**実装の過程・意思決定の経緯・作業ログ・検証ステータスは書かない。**

**叙述（背景・変更点・理由）の素材は `git log <base>..HEAD` と `git diff <base>...HEAD`（3点表記）だけ。** 実装中の会話（レビューを実施した経緯、別タスクの議論、設計判断の往復）は持ち込まない。log/diff に痕跡が無い情報は**叙述には書かない**（参照リンク節だけは例外、下記）。

### 構造を守る
- **構造を壊さない**：見出し・節順・HTML コメントはそのまま。節を増減しない。
- **diff から導けない節**は捏造しない。ただし**埋める材料があれば埋める**：参照リンク節（関連 URL・設計/Figma・関連 Issue）には既知の関連リンク、手順節（動作確認方法・テスト手順）には diff から辿れる再現手順（必要な操作・経路）。これらは叙述ではないので素材限定の対象外。**本当に材料が無い節だけ「なし」と明記**し空欄放置もしない。ここで書くのは手順や参照であって、**検証の合否・実施状況（「確認済み」「レビュー通過」）ではない**。URL は捏造しない（確かに関連するものだけ）。
- **チェックボックス**は原則未チェック。チェックするのは `<base>..HEAD` の diff に**対応する変更が実在する項目だけ**（例：「テストを追加した」は diff にテスト追加がある時のみ）。判断材料が無い項目は未チェックのまま。

### 書く / 書かない
変更は**観点（なぜ／何を）単位**でまとめ、ファイル/行単位で書かない。

書いてよい：
- **何が変わったか**（観点単位の全体像）。
- **制約・未完了の理由**：なぜスタブか・なぜダミー表示か等、diff からは読めない非自明な制約。

書かない（＝実装過程・ノイズ）：
- **実装の細部の列挙**：ファイル名・コンポーネント名・フック名・変数名・定数ファイル名・props・色。diff で読める。
- **設計選択の正当化**：「〜の理由は」「〜に倣う」「〜に準拠する」など、どの実装手段を選んだかの経緯・言い訳。レビュー議論で扱うものであって本文ではない。
- **内部ドキュメント参照**：ADR 番号など、**この PR から辿れない**参照（特に gitignore 等で含まれないもの）。
- **作業・検証の実施状況**：型チェック・lint・レビュー実施済み、手元で動かした経緯。テンプレートに専用節がある時だけそこに簡潔に。
- **自明な機械的差分**：呼び出し側追従・import 整理など。例外は**ファイル移動/リネームで import パス・モジュール名が変わる類だけ**、探索コスト削減のため**理由を書かず1行**残してよい。

### バッククォートは最小限
識別子を機械的に全部囲まない。記号入りコード片や誤読箇所だけ、同じ語は初出のみ。

### バッドプラクティス：実装過程を書いてしまう

実際にダメだった例。意思決定の経緯・辿れない参照・検証ログを書き込んでいる。

```markdown
## 変更点
- 対象ユーザーカードは共有 UserInfoCard を流用せず feature 内に新規実装する。理由は ADR-0002（ピクセルパーフェクト保証と共有コンポへの波及回避）。
- マスク表示の暫定定数を `constants.ts` に集約し、無効化モーダルと詳細モーダルで共用する。

## 備考
- 型チェック・biome・CodeRabbit レビュー実施済み。指摘はプレースホルダ1件のみ。
- 設計判断は ADR（docs/adr）に記録しているが gitignore のため本 PR には含まれない。
```

何が問題か：

- **設計選択の正当化**（なぜ共有コンポを使わないか、ADR-0002 の言い訳）＝本文の仕事ではない。
- **`UserInfoCard` / `constants.ts` など実装の細部**を列挙＝diff で読める。
- **ADR-0002 はこの PR から辿れない**（gitignore）。辿れない参照は書かない。
- **備考が検証ログ**＝作業の実施状況であって変更内容ではない。

良い形（観点単位・diff から読めないことだけ）：

```markdown
## 変更点
- 発行済 API キー一覧から、キーの詳細を確認できるモーダルを追加した。
- 詳細モーダルから既存の無効化フローへ遷移できるようにした。
- 対象ユーザーの一部項目と各種日時は実 API 未接続のためダミー表示（差し替えは別タスク）。
```

## タイトル

**簡潔第一。`<prefix>: ` を除く本体は日本語30文字以内を目安**に、主目的だけを1フレーズで言い切る。変更の列挙・手段・補足はタイトルに入れず本文へ回す。「〜し、〜する」のような複数事項の接続や `（…）` での補足は避け、文末の「〜する」等も削る。

**命名規約の「定義」がリポジトリ内に在るかを網羅的に調べる**（テンプレ探索と同格の必須手順）。**既存 PR やコミット履歴から推測しない**（＝状態に依存しない）。規約は**明示的に定義された情報源**からだけ取る。規約を見落として独自フォーマットで付けるのが最頻の事故。型（`fix:` 等）の**外側**に付くプレフィックス／スコープ／チケット番号を落とさない。**「定義なし」と結論してよいのは、下記をすべて当たって痕跡が無いときだけ。**

定義が置かれうる場所（網羅的に当たる）：

1. **PR タイトル lint（CI で落ちる＝最優先で適合）**：
   ```bash
   grep -rilE 'semantic.?pull.?request|pr.?title|commitlint|release.?please' .github 2>/dev/null
   ```
   `amannn/action-semantic-pull-request`・`.github/semantic.yml`・commitlint・release-please 等の必須形式・許可 type/scope。
2. **規約・設定ファイル**：
   ```bash
   ls CONTRIBUTING.md .github/CONTRIBUTING.md docs/CONTRIBUTING.md CLAUDE.md AGENTS.md commitlint.config.* .commitlintrc* .czrc cz.json 2>/dev/null
   ```
   ＋ PR テンプレ冒頭の HTML コメント（`PULL_REQUEST_TEMPLATE/` 含む）、`package.json` の commitlint 節、`README`・`docs/**` に書かれた命名／ブランチ／PR タイトル規則、`CLAUDE.md`/`AGENTS.md`。
3. **チケット番号の供給元**：**定義された規約が番号を要求する場合のみ**、その値を現在のブランチ名から取る（`git branch --show-current`、例 `feature/ABC-1234-radio-hover` → `ABC-1234`）。確定できなければ捏造せず停止。

適用：

1. **定義あり** → その**構造を完全に再現**して厳格適合。衝突時は **CI で落ちる lint 設定を最優先**。
2. 定義された規約が要求する情報（チケット番号等）が**確定できなければ停止**して聞く（推測・捏造しない）。
3. **定義なし**（上記すべてを当たって痕跡なし）→ フォールバックで `commit` スキル準拠の `<prefix>: <日本語の説明>` 1行。コミット1個ならそのメッセージ流用、複数なら主目的を1本に要約。prefix 混在時は主目的（迷えば `feat` > `fix` > その他）。

**emit 前の自己照合（必須）**：作ったタイトルを、検出した**定義済み規約**と1度照合する。定義が要求する要素（プレフィックス／スコープ／チケット）が欠けていれば違反 —— 付け直す。

## 既存 PR の場合

`gh pr view --json number,url,state` で検出。あれば新規作成せず `gh pr edit <number> --body-file <tmp>` で**本文のみ**更新。

- **タイトルは触らない**（手修正を潰さない）。
- 本文は `<base>..HEAD` から**全面再生成・置換**（手追記は保持されない旨を報告に1行添える）。

## 停止条件（自律実行の例外）

以下では止めて確認・報告する：ベース引数未指定／指定ベースがリモートに無い／テンプレ0件／`PULL_REQUEST_TEMPLATE/` 複数で決められない／タイトル規約が要求する情報が無い／`git push` 拒否（force しない）／git リポジトリでない・`gh` 未認証・差分なし。

停止時は、**そこまでに判明した警告・事実（未コミット変更・現在ブランチ・ベース・差分有無）も併せて伝える**。

## やらないこと

- コミットしない・force push しない。
- テンプレート構造を改変しない（節の増減・並べ替え・コメント削除）。
- **draft 以外で作らない**（常に `--draft`）。
- 停止条件以外で確認を取らない（本文・タイトル案の事前承認も求めない）。
