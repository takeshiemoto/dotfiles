# pr — テンプレート順守で PR を作る

`/pr <base>` で push から PR 作成までを確認なしで自律実行する。最優先はリポジトリのテンプレート厳守。コミット生成は範囲外（`commit` スキルの責務）。未コミット変更があってもコミットしない・警告のみ。

## 停止条件（自律実行の例外）

以下は止めて確認・報告する。停止時は、そこまでに判明した事実（未コミット変更・現在ブランチ・ベース・差分有無）も併せて伝える。

- ベース引数未指定（推測・自動検出しない）／指定ベースがリモートに無い。
- git リポジトリでない／`gh` 未認証。
- ベースに対し差分ゼロ（「PR にする差分がない」と伝えて終了）。
- テンプレート0件（勝手に作らない）／`PULL_REQUEST_TEMPLATE/` に複数あってどれか決められない。
- タイトル規約が要求する情報（チケット番号等）が確定できない（推測・捏造しない）。
- `git push` 拒否（force せず理由を報告）。

## 手順

1. 前提チェック：git リポジトリ・`gh auth status`・ベース引数の3点。
2. 差分確認：`git log <base>..HEAD` と `git diff <base>...HEAD`（3点表記）。未コミット変更があれば「PR に含まれない」と一言警告して続行。
3. テンプレート探索：GitHub 標準配置を大文字小文字・拡張子（`.md`/`.txt`/無し）のゆれ込みで探し、1件ならそれを使う。

   ```bash
   find . \( -path './.github/PULL_REQUEST_TEMPLATE*' \
           -o -iname 'PULL_REQUEST_TEMPLATE.md' \
           -o -ipath './docs/PULL_REQUEST_TEMPLATE*' \) -not -path './.git/*'
   ```

4. 本文生成：[references/body.md](references/body.md) を正として組み立てる。叙述の素材は手順2の log/diff のみ。組み立て後に「字数を削る」パスを1回通す。
5. タイトル生成：[references/title.md](references/title.md) の規約探索・適用・字数削減・自己照合に従う。
6. UI キャプチャ：diff に画面へ見える変更が含まれる PR は、後述「UI キャプチャ」に従って撮影し、本文に貼る。含まれなければ何もしない。
7. push：停止条件を全通過してから `git push -u origin HEAD`（中断する PR のブランチを公開しないため最後に置く）。
8. PR 作成/更新：
   - 既存 PR（`gh pr view --json number,url,state`）があれば `gh pr edit <number> --body-file <tmp>` で本文のみ全面再生成・置換。タイトルは触らない（手修正を潰さない）。手追記は保持されない旨を報告に1行添える。
   - なければ `gh pr create --base <base> --head <current> --draft --assignee takeshiemoto --title "<title>" --body-file <tmp>`。assignee は常に `takeshiemoto` 固定。本文は一時ファイル経由（エスケープ事故回避）。
   - 手順6でキャプチャを撮った場合は、どちらのコマンドにも `--attach '<絶対パス>#<説明>'` を画像の数だけ付ける。
9. 報告：ベース・draft を述べ、URL は半角スペースを挟んで行末に置く（例 `PR を作成した（base: develop、draft）: <URL>`）。URL の直後に文字を続けない（ターミナルのリンク検出が壊れる）。キャプチャを添付した場合は枚数を、撮れなかった場合は理由と「作者が添付すること」を1行添える。

## UI キャプチャ

画面に見える変更を含む PR には、キャプチャを必ず添付する。レビュアーは見た目を diff から再現できないため、文章での描写では代わりにならない。

- 対象の判定：`git diff <base>...HEAD --name-only` に React コンポーネント・テンプレート・スタイル・画像・表示文言の変更が1つでもあれば対象。バックエンドのみ・テストのみ・設定のみの PR は対象外。
- 撮るもの：新規画面・新規要素は変更後だけ。既存画面の修正は修正前と修正後の2枚（前は `git stash` やベースブランチの環境で撮る）。状態が複数ある変更（エラー表示・モード切替など）は状態ごとに1枚。
- 撮り方：ローカル環境で該当画面を実際に表示して撮る（Chrome DevTools MCP か Playwright MCP）。保存先は scratchpad ディレクトリで、ファイル名は `before_<画面>.png` / `after_<画面>.png` のように内容が分かる名前にする。コンポーネントの見た目を手で描いたり、Figma の画像で代用したりしない。
- 貼る場所：本文の「変更点」節の末尾に `![<説明>](<絶対パス>)` を画像ごとに1行で書く。説明は「ユーザー設定のパスワード区画（変更後）」のように画面と前後が分かる短い語。`gh` に同じ絶対パスを `--attach` で渡すと、本文中の参照がアップロード先 URL に置き換わる。
- 撮れない場合：ローカル環境が起動していない・画面に到達する手順が diff から読めない等で撮れないときは、停止せず PR の作成/更新まで進める。本文には画像参照を書かず、報告で理由と未添付である旨を明記する。撮れなかったことを本文には書かない。

## やらないこと

- コミットしない・force push しない。
- テンプレート構造を改変しない（節の増減・並べ替え・コメント削除）。
- draft 以外で作らない（常に `--draft`）。
- 停止条件以外で確認を取らない（本文・タイトル案の事前承認も求めない）。
