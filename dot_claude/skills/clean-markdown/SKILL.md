# clean-markdown — 文章を整える 3 段パイプライン

書き上がった markdown を、AI 臭の除去、装飾の除去、lint 整形の順で仕上げる。内容や主張は変えず、表現と体裁だけを整える。

対象はユーザーが指定したファイル。指定がなければ、直前にこのセッションで作成・編集した markdown を対象にする。

## 適用範囲

- `.md` などファイルへの書き出し。
- Notion、Slack、GitHub PR 本文など外部ツールへの markdown 書き込み。
- ターミナルでのチャット返信そのものは対象外。

## 手順

必ず次の順で実行する。lint を先に実行すると、後の書き換えで再びエラーが入る。

### 1. AI 臭を除く

`stop-ai-slop-jp` のルールを適用する。主体の不在、命題型 H2、壮大化、両論併記、リズムの均一さ、偏愛語を確認し、必要なら構造から書き直す。

### 2. 装飾を除く

次のルールをすべて適用する。

- 太字を使わない。強調は見出しや文の構造で表す。
- コードブロックは実コード、シェルコマンド、設定ファイルの内容だけに使う。ログやプレーンな文章は囲まない。
- 単体のパス、識別子、短いコマンドはインライン code にする。
- 絵文字、水平線、blockquote、callout を使わない。
- 作業者向けの段取りや構成方針など、読者に不要なメタ情報を入れない。

### 鉤括弧を使わない

- 引用や発言は地の文に取り込む。
- 強調目的の鉤括弧は外して素の語にする。
- コマンド、ファイル名、識別子、専門用語はインライン code にする。
- 書名や作品名も素の語で書く。

### 表を使わない

行と列のデータも表にせず、項目ごとの箇条書きに変換する。列が多い場合は見出しと箇条書きの節に分ける。

### 3. markdownlint を実行する

```bash
bunx markdownlint-cli2 --fix <対象ファイル>
```

自動修正されなかったエラーは手で直し、`Summary: 0 error(s)` になるまで再実行する。

lint の修正が手順 1 と 2 の結果を壊す場合は、手順 1 と 2 を優先して書き換えた後に再 lint する。

## 完了条件

- 本文に鉤括弧、表、太字、絵文字、水平線、blockquote が残っていない。
- `bunx markdownlint-cli2 <対象ファイル>` が 0 error で通る。
- 変更前後の diff を確認し、文意が変わっていない。
