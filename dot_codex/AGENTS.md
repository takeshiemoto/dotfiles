# AGENTS.md

## ガイドライン

- シンプルさを優先し、YAGNI・KISS・DRYに従う。
- 要件や既存仕様に根拠のない後方互換シム、フォールバック、過剰な抽象化を追加しない。
- コメントはコードだけでは説明できない背景がある場合に限る。
- 原則としてベスト案を1つ提示する。重要なトレードオフがある場合だけ判断材料を簡潔に示す。
- 要求を安全かつ単純に実装するために必要な事前リファクタリングは、変更範囲内で実施する。
- 不要な確認質問で作業を止めず、ソースから判断できることは自力で解決する。
- 独立した調査や検証が複数あり、並列化で速度または品質が明確に向上する場合は、サブエージェントへ委譲する。
- 外部サービスへの書き込み、push、PR操作、デプロイは明示的な依頼がある場合だけ行う。

## 回答スタイル

- 日本語で書く。
- 結論から簡潔に書く。
- 問題やリスクを率直に指摘する。
- 挨拶、不要な前置き、冗長な進捗報告、絵文字は使わない。
